# 贪吃蛇 DQN 奖励函数设计报告

## 一、问题定义

### 1.1 任务目标

在 30×30 网格世界中训练一个 DQN agent 玩贪吃蛇，需同时满足三个子目标：

- **G1 — 导航觅食**：找到并吃掉随机出现的食物
- **G2 — 障碍回避**：避开 2 个不规则形状、随机移动的障碍物
- **G3 — 自身回避**：避免蛇头撞到自身蛇身

其中 G2 的困难在于障碍物是**动态的**（每步以 ±1 速度在限定区域内移动，10% 概率随机改变方向），agent 需要学会预测其运动轨迹。

### 1.2 核心挑战：稀疏奖励问题

原始奖励设计中，唯一的学习信号是：

- 吃到食物：+10（极少发生）
- 死亡：-10（频繁发生）
- 距离塑形：±1/步（与障碍物回避冲突）

在 30×30 大网格中，蛇初始位置 (5, 10)，食物可能出现在 (28, 28)，曼哈顿距离超过 40 步。加上 2 个移动障碍物阻挡，随机探索吃到食物的概率极低。**实验数据证实：训练 1600+ episodes 后 Score 恒为 0，agent 从未吃到过食物。**

根本原因：**缺乏中间信号**（intermediate reward signal），agent 在得到任何正反馈之前就已死亡，Q 网络学到的全是"一切行为都通向死亡"。

## 二、领域调研

### 2.1 Potential-Based Reward Shaping（Ng, Harada & Russell, ICML 1999）

**定理**：设 MDP 的原始奖励为 R，塑形奖励为 F(s, a, s')。当且仅当存在势能函数 Φ: S → ℝ，使得

```
F(s, a, s') = γΦ(s') − Φ(s)
```

时，最优策略保持不变。任何其他形式的奖励塑形都可能产生次优策略。

**经典反例**：一个足球 agent 被设计为"每次触球 +1"。由于塑形不是势能函数形式，agent 学会在球旁边高频振动以最大化触球次数，而非射门得分。类似地，原始方案中的"靠近食物 +1 / 远离食物 −1"也是非势能塑形，可能引导 agent 学习错误策略。

**势能函数构建**：Ng 等人提出使用启发式估计作为势能：

```
Φ(s) = −d*(s)
```

其中 d\*(s) 是状态 s 到目标的可接受启发式估计（如 A\* 距离）。在贪吃蛇中，用曼哈顿距离作为上界估计：

```
Φ(s) = −Manhattan(head, food)
```

塑形奖励为：

```
F = γ × (−new_dist) − (−old_dist) = old_dist − γ × new_dist
```

**关键性质**：

1. 策略不变性：argmax\_a Q\* 不变
2. 总塑形贡献有界：Σ γ^t F\_t = γ^{T+1}Φ(s\_{T+1}) − Φ(s\_0) ≤ 初始距离
3. agent 无法通过来回走动刷分（积累的塑形奖励被势能差回收）

### 2.2 Artificial Potential Field 奖励（APF-based RL）

来自 PER-D3QN (IEEE 2025) 和 APERN 算法：

核心思想：借鉴机器人路径规划中的**人工势场法**，构建：

- **吸引力势场** U\_att：目标（食物）产生吸引力，距离越远力越大
- **排斥力势场** U\_rep：障碍物产生排斥力，距离越近力越大

奖励函数直接使用势场变化：

```
R_apf = −ΔU_att − ΔU_rep
```

在多篇论文中，APF 奖励相比纯稀疏奖励能将导航成功率提升约 14%。

### 2.3 混合多目标奖励分解（HDCPO, ScienceDirect 2025）

HDCPO（PPO 变体）采用**奖励分解机制**：多个子奖励独立计算后加权求和，通过动态策略梯度权重优先处理安全关键子奖励。

关键经验：

- 子奖励应在相近的量级上（避免某一项主导）
- 安全相关惩罚需要比效率惩罚更强
- 总奖励在单步的期望值不应过大（防止 Q 值爆炸）

### 2.4 每步惩罚 vs 存活奖励

文献和开源项目的共识：**使用小的每步惩罚（−0.01 \~ −0.1），而非存活奖励。**

原因：存活正奖励会导致 agent 学习"无限循环存活"的退化策略——agent 找到一个安全角落绕圈即可积累无限奖励，而不去完成吃食物的核心任务。负的步长成本创建了**效率压力**：agent 被激励用最短路径吃到食物，因为每多走一步就多付一次成本。

### 2.5 调研总结

| 技术         | 成熟度                | 适用性         |
| ---------- | ------------------ | ----------- |
| PBRS（势能塑形） | 理论完备，1999 年至今被广泛验证 | 食物导航引导      |
| APF 排斥势场   | 机器人导航领域标准方法        | 障碍物/墙壁/自身预警 |
| 多目标奖励分解    | 2024-25 年前沿方法      | 三个子目标的权重平衡  |
| 每步惩罚       | 开源项目共识             | 效率约束，防退化    |

## 三、奖励函数设计

### 3.1 总体架构

```
R(s, a, s') = R_food + R_death + R_pbrs + R_danger + R_step
  ─────────   ───────   ────────   ────────   ───────
   终端奖励     终端惩罚   导航引导     安全预警     效率约束
   (稀疏)      (稀疏)     (密集)      (密集)      (密集)
```

四项设计原则：

1. **终端奖励定义真目标** — 吃到食物和死亡是唯一不可塑形的信号
2. **导航用势能引导** — PBRS 保证不扭曲最优策略
3. **安全用渐进预警** — 三层距离 × 三种危险源的矩阵式信号
4. **效率用微量惩罚** — 足够打破死循环，不够主导决策

### 3.2 第一层：终端奖励（定义 MDP 真实目标）

```
R_food  = +10.0   if head == food else 0
R_death = −10.0   if collision(wall | self | obstacle)
```

设计理由：±10 的对称设计使得"吃一个食物 = 避免一次死亡"，两个目标等价。量级适中——不会导致 Q 值过大（梯度不稳定），也不会让信号太弱（学习太慢）。

### 3.3 第二层：PBRS 食物导航引导

**势能函数**：

```
Φ(s) = −Manhattan(head, food)
     = −(|head_x − food_x| + |head_y − food_y|)
```

**塑形奖励**：

```
R_pbrs = γ × Φ(s') − Φ(s)
       = Manhattan_old − γ × Manhattan_new
```

其中 γ = 0.99（DQN 折扣因子）。

**单步效果**：

| 移动方向      | ΔManhattan | R\_pbrs (近似) |
| --------- | ---------- | ------------ |
| 朝食物移动 1 步 | −1         | +1.0         |
| 平行于食物移动   | 0          | \~0          |
| 远离食物 1 步  | +1         | −1.0         |

**理论保证**：

≥ 定理（Ng 1999）：对任意 MDP (S, A, T, R, γ)，若使用 PBRS 塑形，则最优策略 π\* 不变。

证明思路：累积塑形奖励的 telescoping sum：

```
Σ_{t=0}^{T} γ^t × (γΦ(s_{t+1}) − Φ(s_t))
= γ^{T+1}Φ(s_{T+1}) − Φ(s_0)
```

这表明塑形项的总贡献仅取决于初始状态和终止状态的势能差，与中间路径无关。因此 argmax\_a Q\*(s, a) 在所有状态下保持不变。

### 3.4 第三层：多层危险预警

从 APF 排斥力场和 HDCPO 混合奖励中提炼，设计**三层预警体系**：

#### 3.4.1 距离度量选择

使用**切比雪夫距离**（Chebyshev distance）：

```
d_cheb(head, cell) = max(|head_x − cell_x|, |head_y − cell_y|)
```

选择理由：蛇每次移动一格（四方向），切比雪夫距离 d=1 意味着"下一步可能碰撞"，与移动机制一致。曼哈顿距离会低估对角线方向的危险（d\_man=2 的对角线格子实际上一步可达）。

#### 3.4.2 三层预警矩阵

| 危险源      | d ≤ 1 (红色区) | d = 2 (橙色区) | d ≥ 3 (安全区) |
| -------- | ----------- | ----------- | ----------- |
| **障碍物**  | −0.50       | −0.10       | 0           |
| **墙壁**   | −0.50       | −0.10       | 0           |
| **自身蛇身** | −1.00       | −0.20       | 0           |

#### 3.4.3 设计理由

**障碍物 −0.5/−0.1**：

- 适中强度：允许蛇在必要时靠近障碍物（如穿过狭窄通道接近食物），但提供足够的负信号促进回避学习
- 当蛇朝食物走（PBRS +1）同时靠近障碍物（d=1, −0.5），净奖励 +0.49 → 仍为正，蛇不会因害怕障碍物而放弃觅食
- 总障碍物惩罚上限 −2.0，防止多障碍物同时靠近时信号过强

**墙壁 −0.5/−0.1**：

- 与障碍物同量级：墙壁是静态危险，更容易学习，无需更强的信号
- 仅对靠近边界的蛇有效，不影响中央区域的探索

**自身蛇身 −1.0/−0.2**：

- 加强惩罚：蛇身随蛇移动且会形成包围结构，预测难度高，需要更强的信号
- d=1 时 −1.0 ≈ PBRS 的 ±1.0，agent 会倾向于"不动"而非"靠近自己的身体"——这是安全的默认行为
- 避免"蛇咬到自己尾巴"：当蛇长 > 5 后，自身碰撞成为主要死亡原因

#### 3.4.4 局部区域计算（优化）

为提高计算效率，不遍历全网格，仅检查蛇头周围 5×5 窗口内的危险源：

```
danger_penalty = 0
for dx in [-2, -1, 0, 1, 2]:
    for dy in [-2, -1, 0, 1, 2]:
        d = max(|dx|, |dy|)
        if d == 0: continue
        cell = (head_x + dx, head_y + dy)
        if is_obstacle(cell):
            danger_penalty += penalty_table["obstacle"][d]
        if is_body(cell):
            danger_penalty += penalty_table["body"][d]
        if is_wall_adjacent(cell):
            danger_penalty += penalty_table["wall"][d]
```

这同时避免了 agent 对远处障碍物产生无意义的恐惧。

### 3.5 第四层：效率约束

```
R_step = −0.01
```

**量级分析**：

- 100 步生存在没有其他事件时累计 −1.0，相当于 1/10 个食物奖励
- 不会主导决策（PbRs ±1.0 是它的 100 倍）
- 打破"原地不动"的局部最优（静止时 PBRS ≈ 0，累计 −0.01 最终会积累成显著惩罚）
- 创建最短路径偏好：绕远路多花 50 步 = 多付 −0.5 代价

### 3.6 奖励量级对比

模拟蛇在典型场景中的奖励分解：

| 场景              | R\_pbrs | R\_obstacle | R\_body | R\_wall | R\_step | **合计**    |
| --------------- | ------- | ----------- | ------- | ------- | ------- | --------- |
| 空旷区朝食物走 1 步     | +1.0    | 0           | 0       | 0       | −0.01   | **+0.99** |
| 朝食物走+擦过障碍物(d=1) | +1.0    | −0.5        | 0       | 0       | −0.01   | **+0.49** |
| 远离食物+靠近自身(d=2)  | −1.0    | 0           | −0.2    | 0       | −0.01   | **−1.21** |
| 平行移动(距食物不变)     | \~0     | 0           | 0       | 0       | −0.01   | **−0.01** |
| 吃食物             | —       | —           | —       | —       | —       | **+10.0** |
| 撞障碍物死亡          | —       | —           | —       | —       | —       | **−10.0** |

可以看到：

1. 觅食行为始终净正（+0.49 \~ +0.99）
2. 远离食物+靠近危险始终净负（−1.21），但不够阻止必要绕行
3. 危险的惩罚不足以阻止 agent 靠近食物（+0.49 > 0）

## 四、理论分析

### 4.1 策略最优性保持

**命题**：本设计中的 `R_pbrs` 保持原始 MDP（仅 R\_food + R\_death）的最优策略不变。

**证明**：`R_pbrs = γΦ(s') − Φ(s)` 满足 Ng 1999 的充分必要条件。∎

**注意**：`R_danger` 和 `R_step` 是**对 MDP 的修改**，不是塑形——它们改变了最优策略。这是有意的设计选择：原 MDP 中"擦过障碍物"和"远离障碍物"等价（奖励都为 0），我们希望 agent 偏向后者。

### 4.2 稀疏到密集的过渡

原始 MDP 中，从起始状态到吃食物需要 T 步，唯一非零奖励在第 T 步（+10）。Bellman 更新需要 T 次迭代才能将 +10 的信号传播回起始状态。在 30×30 网格中 T ≈ 40，但加上随机死亡，**信号衰减到噪声级别**。

新设计中：

- PBRS 每步提供约 ±1 的信号 → 1 步就能感知方向
- Danger 每步提供 0 \~ −1 的信号 → 即时感知危险
- 终端奖励 +10/−10 仍是最强信号 → 定义了最终目标

### 4.3 奖励尺度与 Q 值稳定性

DQN 的 smooth L1 loss 对异常值不敏感，但 Q 值的绝对大小影响梯度。设计原则：

- 单步奖励范围：约 \[−3.0, +1.0]（不含终端事件）
- 完整 episode 累积奖励范围：取决于表现
- 理论最优：吃 n 个食物 = 10n，减去步数成本 −0.01 × steps
- Q(s, a) 的上界约为 V\_max ≈ 10/(1−γ) ≈ 1000（实际上受 episode 长度约束）

这在数值上对 DQN 的 Huber loss 是友好的。

## 五、实现要点

### 5.1 PBRS 计算时序

关键细节：PBRS 必须在**食物被吃掉之前**计算，使用同一个食物位置：

```python
# 正确顺序
old_dist = manhattan(old_head, food)      # 移动前
new_dist = manhattan(new_head, food)      # 移动后（同一个 food）
reward += old_dist - gamma * new_dist     # PBRS

if new_head == food:
    reward += 10.0                         # 食物奖励
    place_new_food()                       # 新食物位置（不影响本次 PBRS）
```

### 5.2 危险预警的碰撞检测去重

重要：如果蛇因障碍物/墙壁/自身死亡，**不应再计算危险预警**——死亡奖励 −10 已包含所有信息，额外预警会导致双重惩罚。

```python
# 先检查死亡
if collision:
    reward = -10.0
    return obs, reward, True, False, info

# 仅当存活时才计算预警
reward += compute_danger_reward(head)
```

### 5.3 障碍物惩罚上限

多障碍物场景下，总障碍物预警惩罚不超过 −2.0，防止蛇在复杂区域被过强惩罚震慑而拒绝探索。

### 5.4 存活奖励 → 步长惩罚的迁移

原方案 `reward += 0.1` 需改为 `reward -= 0.01`，这是基于文献调研的重要修正——正存活奖励必然导致绕圈退化行为。

## 六、预期效果与评估指标

### 6.1 预期训练曲线变化

| 阶段 | Episodes  | 预期 Score | 预期行为            |
| -- | --------- | -------- | --------------- |
| 早期 | 0-500     | 0-2      | 学会不吃墙壁，偶尔吃到食物   |
| 中期 | 500-1500  | 2-8      | 持续吃到食物，开始绕开障碍物  |
| 后期 | 1500-3000 | 8-20+    | 主动避开障碍物和自身，高效觅食 |

### 6.2 评估指标

- **Mean Score (100-ep)**：核心指标，反映觅食能力
- **Mean Episode Length**：反映生存能力（但不应无限增长）
- **Steps per Food**：效率指标 = 总步数 / 食物数，应逐渐下降
- **Death Cause Distribution**：墙死/障碍物死/自身死/超时的比例变化
