# 🔥 DIN（Deep Interest Network）深度兴趣网络 — 算法学习笔记

> 阿里妈妈 2017 年提出 | KDD 2018 | CTR 预估 | 注意力机制
>
> **一句话总结**：在 Embedding + MLP 的底座上，引入 **Target Attention**，让用户历史行为"看菜下饭"——不同候选商品，历史行为的权重不同。

---

## 一、DIN 到底解决了什么问题？

先想一个场景 👇

> 你昨天逛淘宝，先后看了：**T恤 → 手机壳 → 运动鞋 → 数据线 → 牛仔裤**
>
> 现在系统要给你推一个候选商品：**AirPods**

请问：你历史里的 "T恤" 和 "数据线"，对"要不要点 AirPods" 的参考价值一样吗？

显然不一样。数据线跟 AirPods 同属数码配件，应该权重更高；T恤基本无关，权重应该趋近于 0。

**但传统的 Base Model 做不到这一点。**

**DIN 的核心思想**：DIN简单而言，就是在基础多模态Embedding拼接+MLP的基础上，引入注意力机制（Target Attention），

并且针对工业实际问题优化损失函数正则minibatch aware regularization，激活函数(Dice)，以及评估指标GAUC。



那么我们可以暂且认为**如何添加"注意力"**是核心部分，接下来详细介绍DIN中的attention是如何做的。

在介绍前，我们先梳理一下数据的输入有哪些，Embedding如何设置

---



## 二、输入长什么样？Embedding 怎么设？

DIN 的输入分四大类，全部通过 Embedding 查表变成稠密向量：

### 1️⃣ 用户画像特征（User Profile）

比如 **性别、年龄分桶、消费等级** 等，one-hot编码。每个 group 都是一个离散特征：

```
性别：{男, 女}         → Embedding 矩阵 [2 × 64]
年龄：{18-, 18-24, ...}  → Embedding 矩阵 [N × 64]
...
```

一个用户的所有 group 各自查表，得到各自的 64 维向量，**concat 成一个长向量**。

### 2️⃣ 候选商品特征（Target Item / Ad）

包括 goodsID，shopsID，categoryID的group，one-hot编码。同样每个 group → Embedding 查表 → concat。

每个group可能有几百万甚至上亿个 choice，对应 Embedding 矩阵可能有 `[10^7 × 64]` 量级——这是整个模型参数的大头。

### 3️⃣ 用户历史行为特征（User Behaviors）— 这是关键🔥

multi-hot 编码，历史行为就是"商品特征的多值版本"。比如用户最近点过 6 个商品：

```
goods_ids:     1    54   48   64   29   7
shop_ids:     105    7   74   28  199   3
cate_ids:      1     5   90   70   47  57
```

后续一个用户进入模型后，会根据id查对应的表获取embedding。

这里实际上一个用户的其中一个item是三个embedding(这里就是3个6*64的vector)，

因此为了变成"一个"item，通常concat成6*192。(当然也可以sum/pooling)。当然长度统一为L，不足补0。

### 4️⃣ 上下文特征（Context）

one-hot编码，时间、页面 ID 等场景信息，同样 one-hot → Embedding → concat。

---

**总结一下，一个样本输入，有这样几种特征Embedding：**


| 特征Embedding                                  |
| -------------------------------------------- |
| (1) 1个经concat后的(N·D)维的用户特征Embedding vector   |
| (2) L个经concat后的D维行为特征embedding vector        |
| (3) 1个经concat后的(M·D)维的上下文特征Embedding vector。 |
| (4) 1个经concat后的(K·D)维的候选item特征               |


---



## 三、Base Model 核心处理方式

---

base和DIN模型的差异在于"行为特征"的处理，

base就是将L个行为特征经过Sum Pooling，之后再和其他embedding concat再通过MLP二分类。

## 四、DIN Model核心处理方式

而DIN是通过**行为特征user behaviors和候选商品target item交互**，给L个行为特征赋予注意力权重，加权后再concat+MLP。

也就是说明历史浏览的item并非对候选item同等重要。

### 当然代码中实际交互的细节是

`concat[u, t, u-t, u*t]`（u 就是 user behaviors，t 就是 target item），

然后经过MLP+softmax得到L*1的注意力权重，之后加权得到最终的用户行为特征。

u-t可以提现二者差异，u*t可提现二者交互，总之就是全面利用这两个。

得到权重后，加权原始user behaviors就得到了user interest 向量，进行后续分类头即可。

### 💡 关于 Softmax — 一个小争议

值得一提的是，原论文使用 softmax，后续有工作尝试**去掉 softmax 取得更好效果.,**

因为一般序列长度L都比较长，softmax会稀释很多。

此外，也对于损失函数（BCE）添加一个辅助损失，将Attention加权后的user interest 向量通过一个小 MLP 直接预测点击，

为注意力机制提供额外训练信号，它回答了"attention 本身没有直接监督，怎么保证学对"的问题。

## 六、DIN 的其他工业界优化

### （1）改进激活函数PRELU，提出DICE

DIN 没有直接用 ReLU 或 PReLU，而是提出了一种自适应激活函数：**Dice（Data-adaptive Activation）**。

**PRELU激活函数在负数部分有可学习的斜率，但在正负拐点处始终为0，那如果输入数据的均值并非0，这个拐点并不是最优的。**

因此提出Dice，能够根据**实际数据分布自适应调节激活函数的拐点极其平滑度。**

也就是通过计算数据分布的avg和std自适应移动/放缩激活函数。(**激活函数"迁就"数据**)

**到这，是不是会联想到Batch Normalization？**

BN是把原始数据改造为均值为0方差为1的分布，适配拐点为0的激活函数。(数据"迁就"激活函数)。看似和Dice效果有异曲同工之

妙，但是不能仅依赖BN，由于**推荐领域id稀疏+Emebdding稀疏更新的独特性**，同一个batch内可能会有很多冷门神经元输出，BN

也将其强行"拉正"，这对于主流id而言属于**噪声**。同时BN对Batch大小敏感。

### （2）Mini-batch Aware Regularization

### 先纠正一个常见的理解偏差

"由于Embedding的稀疏性和高维特性，模型很容易出现过拟合"

大多帖子讲解都会这样讲，我个人认为比较容易误解，embedding不是稠密向量吗，为什么会有稀疏性呢?



其实这里的稀疏，是从"更新/激活"的视角来看的。

和标准神经网络不同，神经网络中一个样本会更新所有参数，但Embedding矩阵更新中，一个Batch里只有被用户点击或曝光到的

那些ID，它们对应的Embedding行才会产生非零梯度来反向更新参数(这里的参数就是Embedding里的)，所以更新"稀疏"。



### 那稀疏为什么会引起过拟合呢?

由于推荐领域里样本的长尾特性(类似二八定律，80%的点击集中在20%的商品里)，

so整个Embedding矩阵（如1亿行，每行就是一个ID）中，只有几百行的梯度是非零的。

举个例子：

> 商品 ID = 12345 是个冷门商品，训练集里只出现了 **3 次**。
>
> 这一行 Embedding 有 **64 个参数**。64 个参数只用 3 个样本训练 → 参数数 >> 样本数 → **死记硬背这 3 个样本的标签** → 过拟合。

而热门商品 ID = 00001 出现在 10 万个样本里，64 个参数被充分训练，不存在过拟合。

**这就是推荐系统的长尾困局**：头部商品欠拟合，长尾商品过拟合。

此外具体可详细了解下**one-epoch问题**，[http://xhslink.cn/o/3LgPUPdah6G](http://xhslink.cn/o/3LgPUPdah6G)  (这篇是我认为写的比较全面的)



### 传统方案如何解决这种过拟合呢？

对于这种过拟合，传统神经网络解决方式有很多，比如droupout，L1/L2正则，数据增强等。

其中对于**L2正则**($$L = L_{\text{BCE}} + \lambda \sum W_2^2$$)，损失函数后默认添加的是所有参数的二阶范数来"惩罚"当前参

数更新，但是embedding里只有非零ID行更新，白白遍历计算了"所有参数的二阶范式。



### DIN 的改进：Mini-batch Aware Regularization

两步优化：

1. **只计算被激活的 ID 行** 的 L2 范数（跳过梯度为 0 的绝大多数参数）
2. **自适应惩罚力度**：高频 ID → 减小惩罚（已经学够了，别再过正则）；低频 ID → 增大惩罚（样本少，严防死记）

$$L = L_{\text{BCE}} + \lambda \sum_{j \in \text{activated}} \frac{1}{n_j} \cdot \|W_j\|_2^2$$

其中 $n_j$ 是 ID j 的出现频次，$\frac{1}{n_j}$ 就是自适应惩罚因子——频次越高，惩罚越小。

> 这个细节体现了阿里做工业级推荐的真实痛点：论文里的一个好想法，落到上亿参数的模型上，算力能不能扛住？

### （3）改进评估指标AUC为GAUC

在推荐领域经常会出现这样一种情况:离线模型AUC指标很好，但在线A/B测试并不理想。

**AUC衡量的是什么？**

AUC 衡量的是：随机抽一个正样本和一个负样本，模型给正样本打分 > 负样本打分的概率。

$$AUC = P(\text{score}_{正} > \text{score}_{负})$$

可能比较拗口，如果不理解可以详细搜索，这里不赘述。

但AUC衡量的是模型在数据集这个整体上的效果，实际A/B测试中输入仅是一个用户，当前用户"下一次点击什么"和其他用户毫无

关系。

**AUC衡量的是什么？**

因此提出GAUC，也就是在AUC基础上加一个权重，权重的大小代表用户的活跃程度(点击商品的频率)。

$$GAUC = \frac{\sum_{i=1}^{N} w_i \cdot AUC_i}{\sum_{i=1}^{N} w_i}$$

- $AUC_i$：用户 i 自己的 AUC（只看这个用户的样本）
- $w_i$：用户 i 的权重，通常是**点击次数**或**曝光次数**
- N：用户数
